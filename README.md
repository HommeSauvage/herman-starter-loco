# Herman Loco Starter

<!-- @starter -->
The Loco template behind Herman's wizard. An agent turns it into one user's
product: keep the stack, delete what that product does not need, and replace this
file with the product's README.

It is not maintained for human readers and never deployed as-is.

## What is already wired

- **Loco 1.2 / Rust** — controllers, models, migrations, tasks, workers, mailers, scheduler, SeaORM 2
- **Auth** — register, login, email verification, password reset, magic link. JWT in `Authorization`
- **A reference module** — user-scoped Notes CRUD: ownership enforced server-side, pagination, search, pinned filter, dashboard counts
- **Typed API contract** — DTOs derive `ts-rs`; `cargo test` exports `frontend/src/bindings/`
- **SPA frontend** — React 19 + Vite + React Router 8 + TanStack Query
- **Design system** — Tailwind v4 + shadcn/ui (new-york), light/dark tokens, app shell with sidebar and breadcrumbs, auth screens, loading/error/empty states
- **Agent skill** — Loco's official skill (doctrine, API index, recipes) in `.claude/skills/loco`, mirrored to `.agents`, `.pi`, `.cursor`
- **Gates** — `./scripts/ci-check.sh` runs fmt, clippy, tests, bindings drift and the frontend checks

## The contract

`AGENTS.md` is the operating contract for coding agents — conventions, gates and
floors. Read it before changing anything; this file only explains the starter's
own machinery.

### 1. Read the Loco skill first

`.claude/skills/loco/SKILL.md` routes you to the right file. Read
`starter-app.md` before exploring the tree, and `doctrine.md` before writing
Loco code. `api-index.md` and `sea-orm-index.md` are generated from rustdoc,
so they cannot drift from the installed version.

### 2. Generate, then edit

```bash
cargo loco generate scaffold notes user:references title:string! body:text! pinned:bool!
cargo loco db migrate && cargo loco db entities
cargo test          # also exports the TypeScript bindings
cargo loco routes   # proves it is wired
```

Rust has no autoloading. The generator writes the file *and* the registration;
hand-written wiring is how "the handler exists but 404s" happens.

### 3. Replace this file

The product's README is written in the foundation milestone: the product name,
what it does, how to run it, the demo logins. The starter text is scaffolding.

## Development

| Command | Purpose |
|---|---|
| `./scripts/setup.sh` | Install deps, migrate, seed, build the SPA, install git hooks |
| `./scripts/dev.sh` | Loco on 5150 + Vite on 5173 |
| `cargo loco start` | Serve the API and the built SPA on 5150 |
| `./scripts/ci-check.sh` | The gate: fmt, clippy, tests, docs, bindings, frontend |
| `./scripts/preflight.sh` | One line per environment fact |
| `./scripts/agent-report.sh` | One JSON line: versions, routes, migrations |
| `cargo loco db seed` | Demo users (`user1@example.com` / `1234`) |
| `./scripts/clean.sh` | Sweep stale artifacts and cap `target/` at 8 GB (`--full` = `cargo clean`) |
| `./scripts/sync-skills.sh` | Mirror `.claude/skills/loco` to the other agent dirs |

Demo login: **user1@example.com** / **1234** after `cargo loco db seed`.

`setup.sh` installs a pre-commit hook that runs the full gate
(`./scripts/ci-check.sh`). Bypass it only in an emergency with
`git commit --no-verify`.

## Performance & disk

Rust build artifacts are the biggest thing in a repo like this. The starter is
tuned for an agent loop:

- **Toolchain pinned** in `rust-toolchain.toml` (1.99.1), and CI pins the same
  version. A new stable cannot turn `-D warnings` red behind your back; bump
  both together.
- **Profiles** in `Cargo.toml`: dev keeps line tables for this crate only and
  builds dependencies without debug info; release is thin-LTO, one codegen unit,
  stripped symbols. Measured on a clean tree: `target/` after `cargo test` is
  ~1.6 GB (was ~4.8 GB), and the release binary is ~18 MB (was 29 MB).
- **`./scripts/clean.sh`** removes artifacts untouched for 30 days and caps
  `target/` at 8 GB; `--full` runs `cargo clean`. It prints sccache stats when
  sccache is installed.
- **sccache** is optional locally and enabled in CI. It survives `cargo clean`,
  branch switches and dependency bumps that invalidate the target cache:
  ```bash
  cargo install sccache   # or: brew install sccache
  export RUSTC_WRAPPER=sccache
  export CARGO_INCREMENTAL=0
  sccache --show-stats
  ```
  CI runs it with the GitHub Actions backend **only when the target cache
  misses**: the warm tree needs no compiler cache, and the rebuild after a
  `Cargo.lock` change reuses every crate that did not change.
- **`cargo machete`** runs in the gate (when installed) and in CI, so unused
  direct dependencies cannot quietly add compile time.

## Runtime notes

- Default database is **SQLite** (`sqlite://herman-loco-starter_development.sqlite`); point `DATABASE_URL` at Postgres and flip the `db-postgres` feature for production.
- Development mail is **stubbed**: register, reset and magic-link succeed without SMTP. Set `mailer.stub: false` and run Mailpit (`docker run -p 1025:1025 -p 8025:8025 axllent/mailpit`) to read mail.
- `PORT` changes the API port; the Vite dev proxy reads the same variable.
- `config/<env>.yaml` is the only settings source. Secrets belong in env vars referenced by `get_env`.
- Production does **not** auto-migrate by default: run `cargo loco db migrate --environment production` as a release step, or set `DB_AUTO_MIGRATE=true` for a single-instance deploy.
